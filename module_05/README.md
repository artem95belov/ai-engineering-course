# Модуль 5 — Оркестрация LLM-сценариев (занятия 9–10)

Цепочки LCEL на LangChain: сценарий ПромТеха «классификация → выбор ветки →
ответ или поиск по базе», диалог с памятью поверх RAG и маршрутизация
обращений с передачей человеку.

## Файлы

| Файл | Занятие | Что делает |
|---|---|---|
| `simple_chain.py` | 9 | Полная цепочка сценария: классификация → RAG или генерация → карточка результата |
| `rag_lcel.py` | 10 | Диалог с памятью: переформулировка уточняющих вопросов, скользящее окно истории |
| `multi_chain.py` | 10 | Маршрутизация technical / general / safety на правилах + вилка RunnableBranch |
| `rag_stub.py` | — | Заглушка RAG-звена Модуля 4 (менять не нужно). Контракт: `answer(question) -> {"answer", "sources"}` |
| `rag_adapter.py` | — | Мост к готовому Модулю 4: тот же контракт `answer(question)` поверх `rag_assistant` (менять не нужно) |
| `data/requests.json` | 9 | Демо-обращения для цепочки |
| `data/routing_cases.json` | 10 | 20 контрольных случаев маршрутизации |
| `data/equipment_registry.json` | 10 | Реестр оборудования (копия из Модуля 2) |
| `final_script/` | — | Эталонные решения (не подглядывать до сдачи) |

## Установка

```powershell
# из корня репозитория, с активированным .venv
pip install -r module_05/requirements.txt
```

Модели эмбеддингов и Docker в этом модуле не нужны: поиск по базе пока
закрывает заглушка `rag_stub.py`. Модуль 4 готов: настоящий поиск
подключается одной строкой импорта через `rag_adapter.py` — см. бонус-задание
Занятия 9. Для этого нужны выполненный `module_04` рядом и собранный индекс.

## Запуск

```powershell
cd module_05
python rag_stub.py                # посмотреть, как отвечает заглушка базы
python simple_chain.py            # Занятие 9: цепочка целиком (нужен ключ GigaChat)
python rag_lcel.py --stats        # Занятие 10: замер истории, без ключей
python rag_lcel.py                # Занятие 10: диалог с памятью (нужен ключ)
python multi_chain.py --dry       # Занятие 10: маршруты по 20 случаям, без ключей
python multi_chain.py             # Занятие 10: маршруты + ответы модели (нужен ключ)
```

Пин `gigachat==0.2.1` — сознательный, тот же, что в module_03: свежие версии
SDK (0.2.3+) переключают адрес API на новый `api.giga.chat`, где нет алиаса
«GigaChat», которым пользуются Модули 1–3. Один общий `.venv` курса — значит,
версия SDK одна на все модули. Модель при этом всё равно указываем явно.

## Troubleshooting

- **`404 No such model`** — модель в коде указывается явно: `GigaChat-2`.
  Алиаса «GigaChat» на новом API больше нет.
- **`ModelNotSpecifiedError`** — тот же случай: SDK не подставляет модель
  «по умолчанию», параметр `model` обязателен.
- **`GIGACHAT_CREDENTIALS не найден`** — файл `.env` лежит в корне репозитория
  (не в module_05), внутри Authorization key, а не Client ID.
- **Локальные прогоны работают, а живой запуск падает** — `--dry` и `--stats` сеть не трогают; проверь
  ключ и интернет отдельным запуском `python rag_stub.py` (он офлайн) и
  `python simple_chain.py` (он с сетью).
- **`ImportError: rag_stub`** — запускай скрипты из папки `module_05`,
  а не из корня репозитория.
